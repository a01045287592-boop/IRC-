# 트레이 네 물체 데모 수집 — TRAY4_DEMO_1.0

대상은 **플라스틱 컵 1개, 유리컵 1개, 접시 1개, 휴지 1개**입니다.
사용자는 매 배치마다 네 물체의 **로봇 손목 파지 XYZ(cm)**만 입력합니다.
고정 목적지는 아래에 이미 반영했습니다. 카메라에서 로봇 XYZ로 변환하지 않으므로 이 방식의 수집에는 카메라-로봇 외부 보정이 필요하지 않습니다.

## 1. 설치와 실행

현재 `raccoon-real` 환경의 터미널에서 실행합니다.

```bash
cd ~/Downloads
unzip -n tray4_demo.zip
python ~/Downloads/tray4_demo/install.py --project ~/Raccoonbot_Cafe_Clean
```

설치 위치는 `~/Raccoonbot_Cafe_Clean/raccoon_real_cup/tray4_demo`입니다.
다른 기존 동작/설정 파일은 변경하지 않습니다. 이미 설치된 폴더에는 덮어쓰지 않습니다.

먼저 실제 로봇을 연결하지 않는 테스트:

```bash
cd ~/Raccoonbot_Cafe_Clean
python raccoon_real_cup/tray4_demo/tray4.py self-test
```

카메라 모듈 테스트는 OpenCV가 필요합니다. `raccoon-real`에 OpenCV가 없어 해당 테스트만 건너뛰면 다음 환경에서도 실행할 수 있습니다. 이 테스트는 실제 카메라/로봇을 사용하지 않습니다.

```bash
"$HOME/yolo_ws/.venv/bin/python" raccoon_real_cup/tray4_demo/tray4.py self-test
```

매 에피소드 수집:

```bash
cd ~/Raccoonbot_Cafe_Clean
python raccoon_real_cup/tray4_demo/tray4.py collect --execute
```

터미널에서 차례대로 다음 네 줄을 입력합니다. 각 줄은 `x y z` 숫자 세 개이며 단위는 cm입니다.

1. 플라스틱 컵 1의 파지 손목 XYZ
2. 유리컵 1의 파지 손목 XYZ
3. 접시 1의 파지 손목 XYZ
4. 휴지 1의 파지 손목 XYZ

컵은 **정면(pitch 약 0°)**, 접시·휴지는 **아래(pitch 약 -90°)**를 향한 파지 자세에서 읽은 손목 좌표를 입력합니다. 젓가락/TCP 좌표나 영상 픽셀, 물체 표면 XYZ를 넣지 않습니다. 추가 보정값은 몰래 더하지 않습니다.

기존 읽기 명령은 그대로입니다:

```bash
python raccoon_real_cup/cup_pick_real.py --port /dev/ttyACM0 --read
```

좌표를 확인하면서 물체를 건드려 옮겼다면 최종 위치에서 다시 티칭합니다. 시작 확인 전에는 로봇을 빈 집게의 수평 초기 자세로 돌려놓습니다. 이 시작 자세를 이번 에피소드의 복귀 자세로 저장합니다.

좌표만 저장하고 기구학을 검사하려면 `collect`에서 `--execute`를 빼면 됩니다. 카메라/로봇에 연결하지 않습니다. 출력된 설정 파일로 다시 실행할 때는:

```bash
python raccoon_real_cup/tray4_demo/tray4.py check --setup /실제/설정파일.json
python raccoon_real_cup/tray4_demo/tray4.py run --setup /실제/설정파일.json --execute
```

새 배치에서는 `collect --execute`를 다시 실행해 네 파지 위치를 새로 입력합니다. 이전 배치의 위치를 자동 재사용하지 않습니다.

## 2. 실행 흐름

- YOLO segmentation으로 앞 트레이의 접시·휴지·컵 두 개를 찾습니다. 컵 재질은 기존의 RGB 흰색 비율 방식입니다. 재질 자체를 학습한 YOLO 모델이라고 주장하지 않습니다.
- 플라스틱 컵/유리컵 각 1개가 분리되고 총 네 개가 안정적으로 확인되어야 시작할 수 있습니다. 가림·분류 불확실·중복 검출은 이유를 터미널에 출력합니다.
- 기준점은 **화면에서 가장 앞 트레이의 아래쪽 변 중앙**입니다. 물체 마스크 중심까지의 **2D 픽셀 거리**로 정렬합니다. 정확히 같은 거리이면 ID 사전순으로 정합니다. 깊이/3D 거리나 엔드이펙터 거리가 아닙니다.
- 화면 번호와 터미널의 순서/티칭 좌표를 확인한 뒤 **터미널 Enter**로 시작합니다. 화면에서 S를 누르는 방식이 아닙니다.
- 순서 확정 직전에 다시 비교하고, 실행 중에는 **YOLO 검출·추적·재정렬을 하지 않습니다**. 카메라 창과 저장 이미지 모두 원본입니다.
- 네 물체의 전체 계획을 실제 시작 관절값으로 검사한 후 실행합니다.
- 물체 하나의 파지→처리→놓기→초기 자세 복귀까지 연속 기록합니다. 복귀 후 터미널에서 성공 확인과 다음 실행을 묻습니다. `Y Enter`이면 다음 물체, 그 외 입력이면 중단합니다.
- 네 작업을 모두 성공 확인하면 한 에피소드로 마칩니다. 로봇 연결 종료 후 모든 저장 프레임에 YOLO bbox·중심점 후처리를 하고 검증·학습 표본 변환을 수행합니다.

카메라 창의 Q/ESC 또는 터미널 Ctrl+C는 중단 요청입니다. 통신 단절·시간 초과·기록 오류 시 자동 재연결/자동 재시작하지 않습니다. 중단된 데이터는 실패 상태로 보존합니다.

## 3. 반영한 동작과 고정 목적지

| 용도 | 손목 XYZ(cm) | 자세/동작 |
|---|---|---|
| 휴지통 | `[12.610, 11.823, 9.725]` | 위에서 파지→들기→정면으로 회전→휴지통에서 열기 |
| 접시 음식물 배출 | `[16.074, 6.658, 14.824]` | 아래 -90°로 운반→+10°로 들고 -90°로 복귀, 두 번 |
| 두 컵 액체 배출 | `[13.428, 6.225, 13.165]` | 정면 0°로 운반→4번 관절만 회전해 -90°→0°, 두 번 |
| 접시 배치 | `[12.625, -1.165, 9.676]` | 아래 -90°로 내려가 열기 |
| 유리컵 배치 | `[16.492, -1.089, 10.792]` | 정면으로 도착→4번 관절만 회전해 아래 -90°→열기→상승 |
| 플라스틱 컵 배치 | `[11.313, -0.486, 5.716]` | 정면으로 도착해 열기 |

플라스틱 컵이 한 개이므로 두 번째 컵의 +2.5cm 적층은 없습니다.
기본 이송 높이는 기존 15cm, 속도 설정은 20, 붓기 유지 1초입니다. 집게 명령 후에도 1초를 두어 기존 SDK의 0.5초 대기와 데모의 추가 0.5초 대기에 해당하는 시간을 확보합니다.
모든 물체가 최초 시작 관절 자세로 복귀합니다. 접시·휴지와 두 컵의 전체 기존 계획을 재사용하며, 컵을 들어 올리는 데서 끝내지 않습니다.

기구학·관절 범위·전환 순서를 검사하지만 실제 장애물/충돌과 파지 성공을 자동 측정하지는 않습니다. 여기서의 테스트는 오프라인이며 실제 장비에서의 첫 에피소드가 별도로 필요합니다.

## 4. 기록 형식

저장 위치:

`~/Raccoonbot_Cafe_Clean/raccoon_dataset/tray4_raw/날짜_시간/`

| 파일 | 내용 |
|---|---|
| `config.json` | 이번 배치의 네 티칭 파지점과 고정 목적지/속도/검출 설정 |
| `selection.json`, `initial_rgb.png` | 확정 순서, bbox 네 꼭지점, 마스크 중심, 기준점, 초기 원본 이미지 |
| `plan.json` | 최초 관절 자세와 네 물체의 전체 단계 배열 |
| `rgb_frames/*.png` | 원본 RGB. 선·글씨·번호가 들어가지 않음 |
| `frames.jsonl` | RGB 목표 10Hz, 실제 host 도착 시간·카메라 시간·프레임 번호 |
| `events.jsonl` | 관절 읽기 목표 20Hz, 실제 SDK 명령/모드/집게 명령, 단계, 사용자 결과, 오류 |
| `steps.jsonl` | 활성 동작 중 RGB별 관절 관측과 그 관측 뒤 유지/전송한 목표 action |
| `annotations.jsonl` | 매 저장 프레임의 네 ID bbox·중심점. 미검출/모호함은 null 상태로 보존 |
| `frame_alignment.jsonl` | 대기를 포함한 프레임별 관절·집게 명령·동작·검출 연결. 없는 값은 null |
| `metadata.json`, `audit.json` | 전체/물체별 성공 확인, 오류, 실제 Hz·간격·동기화 검사 |
| `training/episode.npz`, `training/schema.json` | 검증 통과한 에피소드의 정렬된 학습 표본 및 단위/의미 |

프레임·관절을 배열 순번으로 짝맞추지 않습니다. 프레임 host 도착 이전의 최근 관절 읽기 완료 시간을 사용하고, 최대 100ms 이내인 경우만 동작 표본으로 인정합니다. 활성 단계의 영상/제어 표본 간격이 200ms를 넘으면 중단합니다. 실제 평균 RGB 목표 10Hz, encoder 읽기 목표 20Hz 여부를 보고합니다.

SDK encoder는 캐시일 수 있어 20Hz 읽기가 하드웨어 측정 20Hz 또는 노출 동기화를 보장하지 않습니다. 서로 다른 카메라 clock과 host clock의 숫자를 직접 빼지 않습니다.

관절 샘플러가 시작된 뒤 원본 영상 저장을 시작합니다. 연결 실패나 종료 시 일부 프레임의 상태가 없을 수 있으며 이때 없는 값을 만들어 넣지 않습니다. `frame_alignment.jsonl`의 `host_joint_read_age_ms`는 SDK 캐시를 읽은 시각의 나이이지, 하드웨어 센서 측정값의 나이가 아닙니다. 그리퍼는 명령값입니다.

터미널 대기 동안도 원본 프레임과 관절은 보존하지만 `steps`/학습 표본에는 넣지 않습니다. 각 물체의 `segment_id`로 action chunk 경계를 끊어, 긴 사용자 대기나 다음 작업 시작을 이어 붙여 가르치지 않습니다. 파지/붓기 동작 자체의 유지 시간과 모든 복귀 움직임은 포함합니다.

## 5. ACT에서 반드시 구분할 내용

이 코드는 **관절 피드백을 사용해 완료를 확인하는 스크립트 데모 수집기**입니다. 매 프레임을 저장한다고 물체 위치를 보고 경로를 수정하는 시각 폐루프가 되는 것은 아닙니다. 다양한 초기 배치에서 성공한 데모를 모아 정책을 학습하는 용도로 사용할 수 있으며, 학습 후의 시각 피드백 성능은 별도로 평가해야 합니다.

현재 로봇은 수평/수직 고정을 SDK가 담당하므로 이 버전은 다음을 정확하게 저장합니다:

```text
observation_state (5개):
  측정 q1 q2 q3 q4 [radian], 이전 집게 명령 [0=open, 1=close]

action (8개):
  목표 q1 q2 q3 q4 [radian], 집게 명령,
  horizontal / vertical / wrist 모드 one-hot 3개
```

**집게의 실제 열림 폭은 측정하지 못해 null로 기록**합니다. 관측 벡터의 마지막 값은 이전에 명령한 집게 값이며, 실제 상태라고 속이지 않습니다. 첫 관측처럼 이 값이 아직 알려지지 않으면 마스크를 남기고 학습 표본에서 제외합니다.

Action은 **기존 SDK에 유지시키는 단계별 목표**이며 다음 순간 측정된 관절값을 action으로 바꿔 적은 값이 아닙니다. 수평/수직 모드에서는 q1~3을 직접 명령하고 q4를 SDK가 제어합니다. wrist 모드에서는 q4만 명령합니다. 같은 목표의 반복 기록은 의미가 있지만 같은 SDK 명령을 매번 재전송하지 않습니다.

ACT 입력은 현재 이미지와 현재 상태이며 학습 목표는 이어지는 명령 action 묶음입니다. 묶음 길이는 학습 설정에서 정하며, 프레임 누락이나 물체 구간 경계에서는 padding으로 끊습니다. `dataset.py`는 LeRobot ACT의 이미지·상태·action·padding 키를 제공합니다. `bbox_corners`, `bbox_center`, `bbox_valid`는 선택적인 추가 기록이며 ACT의 필수 입력은 아닙니다. 미검출과 모호한 검출은 NaN 및 false로 남고 검출된 bbox도 YOLO 추정치입니다.

따라서 **일반적인 5차원 joint-position ACT 학습/실행 코드에 이 파일을 그대로 넣을 수는 없습니다.** 이 데이터는 `state_dim=5`, `action_dim=8` 및 같은 모드별 실행 의미에 맞춘 ACT 구성이 필요합니다. `dataset.py`가 RGB/state/action/padding을 읽고 구간을 넘지 않는 chunk를 반환합니다. 학습 정책의 출력은 연속값이므로 이후 실제 배포용 모드 선택·출력 검증도 구현/검증해야 합니다. 이 패키지는 미검증 학습 정책을 로봇에서 실행하는 코드를 포함하지 않습니다.

Instruction은 메타데이터로 기록합니다. 기본 ACT가 이 문자열을 자동 사용하지는 않습니다. 대상/순서도 메타데이터이며, 이미지에는 표시하지 않습니다. 추후 목표 조건을 정책에 입력하려면 학습·시연 양쪽 입력에 명시적으로 추가해야 합니다.

전체 네 물체 에피소드 단위로 학습/검증 배치를 분리하세요. 같은 에피소드의 프레임이나 네 하위 구간을 서로 다른 split에 섞지 않습니다. 우선 3~5개를 수집해 `audit.json`과 실제 동작 결과를 확인하고 늘리는 것이 좋습니다.

## 6. 후처리 재실행/검증

```bash
python raccoon_real_cup/tray4_demo/tray4.py annotate /실제/에피소드폴더
python raccoon_real_cup/tray4_demo/tray4.py audit /실제/에피소드폴더 --export
```

후처리 bbox는 RGB 흰색 분류를 포함한 추정치입니다. 각 종류가 유일하게 검출될 때 의미상 ID를 붙이며, 화면 밖 물체의 마지막 bbox를 복사하지 않습니다. 가림/회전 중 재질 오분류가 생길 수 있고, 확실한 물체 추적 ID라는 보장은 없습니다. 불확실한 컵과 중복 검출은 별도로 남깁니다.

실패·빈 집게 테스트·시뮬레이션·미확인 결과·기록 누락 에피소드는 성공 학습 데이터로 자동 내보내지 않습니다. 데이터 검사 통과는 기록 형식/시간 정합성과 사용자 성공 확인에 관한 것이며 물리적 성공을 센서로 검증했다는 뜻은 아닙니다.

## 7. 구현상 변경 범위

`vendor/`에는 제공받은 기존 전체 동작 코드 사본과 SHA-256을 보존했습니다. 기존 파일을 덮어쓰지 않고 그 계획 함수들을 호출합니다. 네 물체 이름·고정 목적지·복귀·수집 루프·터미널 절차를 새 진입점에서 연결합니다.

SDK 1.7.3의 공개 `write` API로 동일한 자세 모드/각도/집게 장치 명령을 비동기 전송합니다. 원래 SDK 함수의 내부 대기 대신 관절 피드백과 시간 기반 단계 대기로 진행하므로 영상과 encoder 수집이 대기 중에도 계속됩니다. 속도를 임의로 40 이상 올리거나 연결 끊김 예외를 무시하지 않습니다. 실제 통신 단절의 전원/USB/펌웨어 원인을 이 코드가 해결했다고 주장하지 않습니다.
